# Proxmox Image Determinism V1

## Invariant

Every image reference in a versioned Proxmox deployment manifest must resolve
to exactly one immutable set of bits. A reference is deterministic only when it
carries an explicit `@sha256:<64 hex>` manifest digest.

A tag is not a pin. `latest`, a bare name with no tag, a moving major or minor
tag such as `postgres:16-alpine` or `redis:7-alpine`, and an exact-looking
release tag such as `public.ecr.aws/supabase/kong:2.8.1` are all mutable: the
registry may repoint any of them at different bits at any time. Two deployments
of the same commit would then run different code, and the manifest would no
longer describe what is deployed.

A readable tag may be kept in front of the digest —
`postgres:16-alpine@sha256:57c72fd2…` — and should be. The tag documents intent
for a human reader; the digest is what the invariant rests on.

## Scope

The invariant covers the versioned manifests enumerated in
`infra/proxmox/image-determinism-policy.json`:

- every tracked `infra/proxmox/*-docker-compose.yml` artifact, including
  artifacts added after this contract was written, which are discovered rather
  than listed; and
- `infra/swarm/vibemind-stack.yml`, the source of truth from which the Proxmox
  phase manifests are generated by `infra/proxmox/extract_compose.py`.

The Swarm stack is in scope because a pin that exists only in a generated phase
manifest is erased the next time that manifest is regenerated. The pin has to
live in the source.

## The only admissible exception

Images built on the deployment host are never pushed to a registry, so no
manifest digest exists for them and none can be invented. These are the only
references that may remain unpinned, and each one must be enumerated
individually, with a reason, in the `waivers` list of
`infra/proxmox/image-determinism-policy.json`.

The waiver list is a closed, auditable set. It is rejected when:

- a waiver carries no reason, or an empty one;
- a waiver covers an image a registry could resolve — anything carrying a
  registry host or a namespace, or a single-segment official image name. Such
  an image must be pinned, not waived; or
- a waiver matches no reference in any in-scope manifest. A waiver that has
  outlived its image is removed, not left behind.

A waiver records that determinism is currently unattainable for that reference.
It does not make the reference deterministic, and it is not a place to park
registry images someone would rather not pin.

## Deployment consequence

Deployment readiness fails closed on any violation. `infra/proxmox/image_determinism.py`
exits 2 and reports `ready: false` when it finds a floating reference, an
inadmissible or stale waiver, an unreadable or unparsable policy, an in-scope
manifest that is absent, untracked, uncommitted, or modified in the working
tree, or an untracked file that matches a discovery pattern and would therefore
ship without review.

Every decision is made from tracked, committed, unmodified repository content.
The check never contacts Proxmox, a Docker daemon, a registry, or any host, and
it proves nothing about a running system: `deployment_proven=false` and
`golden_path_proven=false` remain true. A reachable registry, an image already
present in the host's image store, or a successful earlier deployment never
overrides this rule.

## Rotating a pin

Changing a digest is a reviewed content change, not maintenance. The procedure —
including how digests are resolved read-only, without a Docker daemon — is in
`docs/runbooks/proxmox-image-pinning.md`.
